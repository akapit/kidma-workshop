# דף נחיתה

**מה זה:** בונה דף נחיתה בעברית, עמודה אחת באמצע, שנראה טוב קודם כל בטלפון, ומעלה אותו לאוויר.
**איך מדבר:** כמו שכתוב ב-`CLAUDE.md` (חוקי המשרד). בגובה העיניים, בלי שפה של פרסומת. את הטקסטים כותב לפי הסקיל copywriting, אם הוא מותקן.

## מה קורא לפני שמתחיל
- `CLAUDE.md`
- כל קובץ בתיקייה שמתאר את העסק, המחירים או הלקוחות (למשל `business/`)
- דוגמאות שהמשתמש נתן: דף שהוא אוהב, מודעה שעבדה, הודעה ששלח ללקוח

## איך עובד
1. **מראיין קודם, שאלה אחת בכל פעם.** לא כותב מילה בדף לפני שיש תשובות ל:
   - מה מציעים, ולמי בדיוק
   - מה הפעולה האחת שהגולש צריך לעשות (וואטסאפ, טלפון, הרשמה)
   - מה הבעיה שהלקוח מרגיש, במילים שהוא עצמו אומר
   - מה הוא מקבל בפועל, ומה המחיר (אם מציגים)
   - למה לסמוך עליכם: ניסיון, לקוחות, תמונה אמיתית
   - מה הלקוח שואל לפני שהוא מחליט
2. **מציע שלד לפני שבונה:** כותרת, תת כותרת, ורשימת החלקים בדף. מחכה לאישור.
3. **בונה קובץ אחד:** `landing/<שם-קצר>/index.html`, עם התמונות באותה תיקייה. נפתח בדפדפן בלחיצה, בלי התקנות. לעיצוב (שאלות על המותג, בחירת פלטה, משטחים, כפתורים, טופס): לפי הסקיל landing-design, אם הוא לא נטען: `../landing-design/SKILL.md`.
4. **פותח את הדף בדפדפן** ומבקש מהמשתמש להסתכל גם ברוחב של טלפון.
5. **מתקן לפי הערות.** כשהערה היא כלל שיחזור (למשל "כפתור תמיד בצבע בולט"), מציע לשמור אותה ב-`CLAUDE.md` תחת "העדפות לסקילים" (עדכון של התוסף מחליף את קובצי הסקיל, חוקי המשרד נשארים).
6. **מעלה לאוויר רק כשהמשתמש מבקש** (ראו "העלאה לאוויר").

## איך הדף נראה
את המראה עצמו קובע landing-design. מה שהסקיל הזה מחליט, ו-landing-design מכבד:
- עברית מימין לשמאל, עמודה אחת באמצע המסך, רוחב קריאה נוח. שתי עמודות רק להשוואה אמיתית
- גופן Assistant מ-Google Fonts. טקסט גוף לפחות 18px בטלפון
- סדר מומלץ: כותרת וכפתור, הבעיה, מה מקבלים, איך זה עובד (3 צעדים), מי אני (עם תמונה אמיתית), שאלות נפוצות, כפתור אחרון
- כפתור אחד שחוזר לאורך הדף, באותו צבע ובאותו נוסח
- כפתור וואטסאפ: קישור `https://wa.me/972XXXXXXXXX?text=` עם הודעה מוכנה מראש
- כותרות בלי נקודה בסוף. משפטים קצרים
- תמונות קלות (עד כ-300KB כל אחת), עם תיאור טקסט

## אף פעם לא
- להמציא המלצות, מספרים, לקוחות, מחירים או תוצאות. אם חסר, שואל
- להעתיק טקסט או עיצוב מדף של מישהו אחר. השראה כן, העתקה לא
- לבקש מהמשתמש סיסמה או פרטי כרטיס
- להעלות לאוויר בלי שהמשתמש ביקש

## העלאה לאוויר (GitHub ואז Vercel)
בלי התקנות על המחשב (לא Node ולא npm), הכל בדפדפן. צריך חשבון GitHub (יש מהגיבוי) וחשבון Vercel (נכנסים אליו עם GitHub).

**הערה אחת לפני שמתחילים, בשורה אחת:** התוכנית החינמית של Vercel (Hobby) מיועדת לשימוש אישי ולא מסחרי. דף שמוכר או מביא לקוחות לעסק נחשב מסחרי, ולכן כדאי לשקול את התוכנית בתשלום (Pro), או את Netlify (ראו למטה). ההחלטה של המשתמש.

1. מוודא שבתיקייה `landing/<שם-קצר>/` יש `index.html` ושכל התמונות בפנים, ושאין בתיקייה הראשית סיסמאות, מפתחות או קובצי `.env`
2. בודק שהתיקייה הראשית מחוברת ל-GitHub. אם לא: מציע להקים מאגר **פרטי**, כמו בסקיל `wrap`
3. שומר גרסה ומעלה ל-GitHub, **רק אחרי שהמשתמש אישר**
4. מנחה את המשתמש, צעד אחד בכל פעם (את הלחיצות הוא עושה, לא Claude):
   - נכנס ל-`https://vercel.com/new` עם GitHub
   - בוחר את המאגר ולוחץ Import. אם המאגר לא מופיע: Adjust GitHub App Permissions, ובוחרים אותו
   - ליד Root Directory לוחץ Edit ובוחר את התיקייה `landing/<שם-קצר>`
   - Framework Preset: Other. בלי Build Command
   - לוחץ Deploy
5. תוך כמה שניות יש כתובת שמסתיימת ב-`vercel.app`. בודקים שהיא נפתחת בטלפון, בלי כניסה
6. עדכון אחר כך: מתקנים בקובץ, ומבקשים "תעלה ל-GitHub". Vercel מפרסם לבד תוך דקה
7. שומר את הכתובת הסופית בקובץ README של הדף, או בשורה ב-`CLAUDE.md`

## אפשרות שנייה: Netlify
- **בלי GitHub (Netlify Drop):** נכנסים ל-`https://app.netlify.com` (בלי כניסה הדף נעול בסיסמה זמנית). Claude פותח את תיקיית הדף ואת `https://app.netlify.com/drop`, והמשתמש גורר את התיקייה. תוך שניות יש כתובת `netlify.app`. עדכון: גוררים שוב את התיקייה לעמוד האתר
- **דרך GitHub:** באותה צורה כמו ב-Vercel: Add new project, Import from Git, ובהגדרות Base directory = `landing/<שם-קצר>`, בלי Build command, ו-Publish directory ריק או `.`
- לבדוק את תנאי התוכנית החינמית של Netlify לשימוש עסקי לפני שמסתמכים עליה
